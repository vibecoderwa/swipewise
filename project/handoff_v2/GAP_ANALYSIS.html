TL;DR

The repo is a working web prototype, not the spec'd app

It nails the data plumbing — Plaid, categorization, insights, credits. It's missing the entire pre-swipe layer, which is the product's reason to exist.

Biggest gap

Platform mismatch. The FRD specifies an iOS-first Expo / React Native app with native Swift widgets. The repo is a web app (Vite + React DOM). No Expo, no React Native, no WidgetKit, no geofencing, no push.

That's not a bug — it's a deliberate prototype-first move — but it means roughly half the FRD has zero implementation surface yet.

What's solid

Plaid Link → exchange → sync → categorization → insights → credit tracking. The recommendations engine even implements FR-ENG-06 confidence (high/medium/low based on net-value gap). Auth flow with phone + OTP is wired (mocked SMS).

What to do next

Two parallel tracks: (1) finish the analytics layer in the web prototype to validate the model end-to-end; (2) start the Expo migration with M0 skeleton, porting core/rewards.ts first.

Bigger structural gaps

Beyond the line-item misses, four shape-of-the-product issues stand out.

1 · Platform — web prototype, not iOS app

  • No Expo project. package.json lists react+react-dom+vite, not expo or react-native.
  • No iOS / Xcode project, no app.json, no ios/ or android/ directories.
  • No WidgetKit target, no App Group, no widgetData.json bridge.
  • No expo-location, expo-notifications, or background task setup.

2 · Engine isn't shared between client & server

  • FR-CARD-01 specifies a single core/rewards.ts imported by both. Today the logic lives only in api/cards.js + api/recommendations.js and the client always calls the API.
  • This blocks FR-ENG-05 (offline re-rank) and makes future TS migration harder.

3 · Pre-swipe layer is entirely absent

  • No nearby-merchants endpoint. No geofence registration. No push delivery.
  • The app today is a reflective analytics tool. The FRD positions the pre-swipe moment as primary.

4 · Security model is prototype-grade

  • x-user-id header auth — anyone with a UUID is "logged in." No JWT, no signed sessions.
  • Plaid access_token stored in SQLite plaintext.
  • OTP code is hardcoded to 421906 in non-production.
  • All fine for sandbox / Replit demo; none of it is FR-SEC-compliant.

Recommended next steps

If staying on web for now

  • Expand the category map from 7 → 15 (FR-TX-04). Many recos hide behind the "other" bucket today.
  • Build the timeline series + period toggle to validate FR-ENG-02 / FR-HOME-04.
  • Wire confidence (already in API) into the home reco rows — visible payoff for free.
  • Add the Durable Travel Credit hero on the credits screen — signature design moment.
  • Backfill 24 months in /api/sync using /transactions/sync + cursor.

To start the spec'd app

  • npx create-expo-app in a sibling repo. Port the React DOM screens to React Native one-by-one.
  • Lift api/cards.js + api/recommendations.js into core/rewards.ts (TS). Server imports from there.
  • Add /merchants/near using merchant inference + a geocode source. Without this, the entire pre-swipe layer is blocked.
  • Scaffold the WidgetKit target after Medium-A widget design is approved.
  • Replace x-user-id auth with a real JWT + refresh-token issuance on OTP verify.
